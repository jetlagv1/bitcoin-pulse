# Native OWL render check

Run `./tools/verify-omalauncher.ps1` from PowerShell with Java 17 / Android SDK configured and the Android project's Gradle dependencies available. The helper can reuse this workspace's local Android environment; elsewhere it uses the Gradle wrapper. `-RefreshSources` re-downloads the pinned upstream files. `-RecordedData` reuses existing recorded API responses (only missing response files are downloaded).

The script downloads the **official Omalauncher parser and Compose renderer** at commit `edab9fba94d2d491b8ef474aa74e5715cae7db18`, plus its MIT license, into an ignored tools cache. The checked-in Kotlin files supply deterministic launcher-service fixtures. Only an unrelated upstream point-map helper gets an equivalent block-body syntax adjustment for Kotlin 2.1; text measurement, layout, Canvas rendering, colors and input handling remain upstream code.

An init script temporarily adds these files to the Android **test** source set. They are not part of production APKs/AABs or ordinary tests. Public Kraken/mempool.space responses are recorded for the run. The test loads the actual packaged `bitcoin-pulse.owl`, evaluates its real data expressions and renders it with Robolectric's native graphics at 320, 360 and 390 dp wide and 840 dp high. A deliberately conflicting green launcher palette and monospace default exercise the explicit colors and sans-serif text.

The check asserts no text overflow/ellipsis, horizontal bounds, visible footer, opaque background, red and green pixels within the candle plot, working cloud on/off (including visible boundary pixels), and working EUR/USD, daily/weekly and refresh taps. The compact −/+ controls are tapped through 24/36/60/90/120/180/270 candles, including both bounds and independent period state. Cloud points at zoom extremes and all cloud points at the default zoom are compared numerically with the production Kotlin calculator for EUR/USD × all three periods. Captures are under `app/build/reports/omalauncher-native/`. This validates widget content under an upstream renderer with recorded data, **not a complete installed launcher, its outer frame, scheduling, import flow or physical device**.

OWL 4.0 adds one/two-chart selection, per-slot period menus, independent currency/period caches, and corresponding real-tap and empty/failed-feed tests. The host draws a complete frame after each remeasure so hit testing follows moved controls.

Appearance parity: run the regular Android tests, this OWL check, then python tools/check-widget-appearance.py. WidgetVisualFixture provides identical synthetic data to both real renderers at 360 x 840 dp. Captures and anchor reports are under app/build/reports/widget-parity/.

OWL 4.2 moves graph count into Bitcoin Pulse's Widgets settings. The import carries the selected count; independent previously imported copies need replacement. Default grid is 4×5 and vertical resizing to 4×6 remains enabled. Compact presentation uses available height for plots and condenses metadata. OwlResizeTest exercises both counts at 320×400, 320×480 and 320×560 dp with actual touch events. It runs in a fresh test JVM, separately from OwlRenderTest, because Compose retains frame scheduling state across the two independent UI suites. Explicit snapshot notification and full layout/draw frames keep hit testing current. Captures are under app/build/reports/widget-resize/.

OWL 4.3 uses a weighted Canvas for a single chart with all metadata retained. Its drawing coordinates use the measured Canvas height. OwlResizeTest verifies exact growth across the former 600 dp threshold up to 840 dp, metadata visibility and inline controls without androidApp actions. Current Android widget period titles also use inline broadcasts; WidgetInlineTest exercises the production RemoteViews clicks and receiver. Legacy WidgetChartPickerActivity remains only for previously issued PendingIntents.

The appearance comparator also checks eight single/two-chart resize variants (400–840 dp) against Android RemoteViews. Currency taps remain inside each widget; the per-widget values are independent. Wider zooms hide the crowded Cloud axis caption while retaining the projected cloud.


Mini 1×1: OwlMiniTest loads the actual bitcoin-pulse-mini.owl through the official compiler/renderer at 40×40, 56×56, 64×64, 80×72, 80×88 and 120×120 dp. It checks full block/fee text, price and label visibility, text bounds/overflow, independent EUR/USD instances, real touch switching, failed-feed cache retention and missing-value dashes. Captures are under app/build/reports/miniwidget/owl-*.png. The ordinary OwlMiniImportTest checks the app's actual import intents and decoded initial currencies. The native 1×1 layout is covered by MiniWidgetTest; both normal-size captures are retained in docs/design.


Adaptive OWL 5.0: OwlAdaptiveTest follows the same instance through mini, enlarged mini, compact, richer compact, network, and back again, for all three import variants. It verifies retained currency/periods/count/cloud/zoom, real in-widget taps, selected candle-source activation only in network mode, and fitting compact/mini text. The three variants are generated from bitcoin-pulse.owl with python tools/sync-owl-variants.py. Native AdaptiveWidgetTest additionally verifies all provider types, large system text, Android exact-size RemoteViews selection and history-fetch scope for multiple orientation sizes. Test captures are in app/build/reports/adaptive-widget.
